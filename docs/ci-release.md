# CI 运行包部署

原有一键安装命令保持不变。目前默认仍为源码构建；为首次制品发布保留兼容窗口。使用 `PROJECT_DEPLOY_MODE=ci` 运行安装器可下载已经通过 CI 的运行包，例如将原命令中的 `sudo bash` 改为 `sudo env PROJECT_DEPLOY_MODE=ci bash`。`PROJECT_DEPLOY_MODE=source`、`--source-dir` 或 `--rebuild` 使用源码构建。

CI 在 Ubuntu 22.04 构建 React/Vite 的客户端与 SSR 文件，打包后只保留运行依赖，并在 x64、ARM64 上启动解包后的服务。服务器校验 SHA-256 和提交身份后，在独立版本目录内准备新版本，健康检查通过后保留为当前版本。启动失败时恢复原服务；配置和数据沿用现有目录。

部署清单只有在全部必要检查通过、两个架构均可用且仍是 main 最新提交时才发布。清单引用固定 `deploy-<完整提交号>` 标签下的包。无可用制品或校验失败会停止更新并保留现有服务，可明确选择源码模式处理。

运行内容未变时，只核对清单和服务健康，不重复下载包、安装项目依赖、构建或重启。文档、测试和 CI 工作流变更不会单独导致服务重启。安装日志区分已经检查的提交与实际运行产物提交。
