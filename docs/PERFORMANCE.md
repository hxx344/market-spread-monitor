# 前端性能验证

2026-09-16，以 `b9b61a4` 为优化前基线。使用同一份真实归档数据：原油 5,000 根 15 分钟记录、海力士小时历史；本地生产构建、独立 SQLite、关闭外部采集与消息发送。Chromium 每轮清空浏览器缓存，桌面宽 1,440，手机宽 390，并对手机场景设置 4 倍 CPU 降速。各场景运行 3 次，以下为中位数，属于本地受控测量，不是线上用户指标。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 桌面打开原油全部明细 | 808 ms | 28 ms |
| 模拟手机打开原油全部明细 | 3,297 ms | 47 ms |
| 明细首屏生成的记录数 | 5,000 | 200 |
| 模拟手机切换全部历史 | 56 ms | 35 ms |
| 模拟手机批量处理 200 次指针移动 | 638 ms | 11 ms |
| 首屏重复请求原油、海力士价格历史 | 2 次 / 450,753 字节 | 0 次 / 0 字节 |
| 首页 HTML 解码后大小 | 584,155 字节 | 569,347 字节 |

明细优化后每页 200 条，翻页仍可访问所有原始记录；并非把 5,000 条全部绘制耗时降到了 47 ms。指针测量是同一任务内连续派发 200 个事件，再等待两次绘制帧：新版在一帧内只处理最后一次位置，因此这一数字反映事件合并效果，不应当作真实设备的 INP。

## 实现

- 首屏直接使用本次服务器读取的历史；浏览器不立即重复获取。若没有首屏历史或它已在传输、恢复过程中停留超过 60 秒，则立即读取。报价仍立即刷新，历史每 60 秒继续检查，手动刷新不受影响。
- 去掉首屏已经不使用的原油日线数据，日线 API 与数据库保持可用。
- 原油明细分页；区间、统计、曲线和累计资金费继续使用完整数据。
- 指针处理按绘制帧合并，二分查找最近的实际观测；保留缺口、较早点优先的等距规则和键盘逐根查看。离开图表会取消待处理提示。
- 历史价格不变时保留曲线与表格；资金费仅状态变化时更新状态文字。两腿的任何价格修正、时间变化、新增记录或缺口变化都会重新处理。
- 原油迷你图缓存由各自面板持有，报价刷新复用历史点；更新历史来源时间和过期状态时仍保留准确标记。格式化时间时复用格式器。隐藏面板不绘制原油价格图，重新打开时按新尺寸恢复。

## 验证范围

单元测试检查定时刷新与卸载取消、二分查找和缺口、全部分页无遗漏无重复、价格修正识别、历史与当前报价分离。浏览器检查原油区间、明细翻页、键盘和指针、相同历史刷新、历史修正、缺口、断网首屏保留、市场切换及 320/390/768/1,440 宽度。

## CEX / DEX 合约监控（2026-09-19）

新增模块不逐条推送交易所消息。后台维护有界的最新报价 Map，同一合约在一个周期内的更新合并，5 秒批量写入 SQLite；没有订阅页面时不生成推送帧。平台状态计数单次遍历报价完成，每次广播只计算、序列化一次供所有客户端共用。

SSE 首次发送完整快照，随后每秒只发送变化的合约；价格数值未变时，最多每 5 秒补发一次原始价格时间确认，30 秒用完整快照校准。价格变化无需等 5 秒。支持流式 gzip；慢客户端跳过帧后必须先重建完整基线，缓冲超过限制则断开重连，不能无限堆积。两腿的原始报价时间及过期规则不因缓存、重连、压缩或资金费消息改变。

前端首次进入才加载合约模块；只启动 SSE，失败或超时才读取 HTTP 快照，避免双份首屏下载。增量按合约键合并，未变的报价和数组保留引用；排名缓存只在报价、筛选、平台可用性或过期边界改变时失效。列表每页最多 30 条、报价详情按需展开。切换市场或隐藏页面关闭 SSE 和请求，后台继续采集；实际浏览器验证切换到原油后，合约 SSE 客户端数量从 1 降为 0。

可复现检查：

```powershell
node --experimental-strip-types tests/perpetual-performance.mjs
```

环境为 Windows 原生 Node.js 24.15.0、Intel i5-14600KF，未使用 WSL。下面是一次受控测试：5,000 条报价、1,000 标的、5 平台、100 帧，每 10 帧改变 1% 报价；各行计量范围不同，不代表公网端到端延迟，也不代表高波动行情固定节省同一比例。

| 测量 | 结果 |
| --- | --- |
| 排名全表计算次数 | 200 → 10 |
| 对应累计排名计算时间 | 215.51 → 14.33 ms |
| 完整 JSON / 50 条更新增量 JSON | 1,776,143 / 19,842 字节 |
| 该受控增量帧 gzip 后 | 915 字节；测试数据重复度较高 |
| 后台 5,000 报价快照统计 | 平均 0.21 ms |
| 后台增量检测 | 平均 2.83 ms |
| SQLite 首次 5,000 条写入 | 48.38 ms |
| SQLite 50 条增量批次写入 | 平均 6.37 ms |

另用真实公开 WS 同时连接全部 10 平台，收到约 4,300 条合约报价、50 条分片连接；当时一个活跃页面的单帧处理采样约 12–14 ms，写入批次采样约 38–80 ms。该次真实帧变化约 1,200–2,000 条，未压缩增量约 0.64–1.02 MB，不能用上述 1% 受控场景的 98.9% 缩减率替代实际行情表现。

运行时预留只读诊断 `/api/monitors/perpetual/diagnostics`，沿用登录保护，显示 `quotes`、`connections`、`clients`、`pendingWrites`、`lastWriteMs`、`lastPublishMs`、`frameBytes`、`lastFrameUpdates`。`frameBytes` 是压缩前大小；`lastPublishMs` 包括汇总、序列化和写入发送缓冲，不包含异步压缩及公网传输耗时。通过这些字段判断行情覆盖增加、连接重试或慢客户端对资源的影响，无需开启逐条行情日志。

回归测试覆盖增量删除/完整校准、无基线恢复、断流过期、慢客户端跳帧重建、身份变化清空旧价、存储失败重试，以及保持 SSE 打开的服务优雅退出。桌面及 390px 手机页面验证搜索、全部报价、平台明细和市场切换，无页面横向溢出。
