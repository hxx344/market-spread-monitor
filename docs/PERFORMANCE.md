## 实现

- 首屏直接使用本次服务器读取的历史；浏览器不立即重复获取。若没有首屏历史或它已在传输、恢复过程中停留超过 60 秒，则立即读取。报价仍立即刷新，历史每 60 秒继续检查，手动刷新不受影响。
- 去掉首屏已经不使用的原油日线数据，日线 API 与数据库保持可用。
- 原油明细分页；区间、统计、曲线和累计资金费继续使用完整数据。
- 指针处理按绘制帧合并，二分查找最近的实际观测；保留缺口、较早点优先的等距规则和键盘逐根查看。离开图表会取消待处理提示。
- 历史价格不变时保留曲线与表格；资金费仅状态变化时更新状态文字。两腿的任何价格修正、时间变化、新增记录或缺口变化都会重新处理。
- 原油迷你图缓存由各自面板持有，报价刷新复用历史点；更新历史来源时间和过期状态时仍保留准确标记。格式化时间时复用格式器。隐藏面板不绘制原油价格图，重新打开时按新尺寸恢复。

## CEX / DEX 合约监控首版基线（2026-09-19，ce17afe）

本节记录首版实现与当时的受控测量；其全市场真实负载问题和后续修复见下一节，不能据 1% 报价变化场景推断 2 核服务器实际资源占用。

新增模块不逐条推送交易所消息。后台维护有界的最新报价 Map，同一合约在一个周期内的更新合并，5 秒批量写入 SQLite；没有订阅页面时不生成推送帧。平台状态计数单次遍历报价完成，每次广播只计算、序列化一次供所有客户端共用。

SSE 首次发送完整快照，随后每秒只发送变化的合约；价格数值未变时，最多每 5 秒补发一次原始价格时间确认，30 秒用完整快照校准。价格变化无需等 5 秒。支持流式 gzip；慢客户端跳过帧后必须先重建完整基线，缓冲超过限制则断开重连，不能无限堆积。两腿的原始报价时间及过期规则不因缓存、重连、压缩或资金费消息改变。

前端首次进入才加载合约模块；只启动 SSE，失败或超时才读取 HTTP 快照，避免双份首屏下载。增量按合约键合并，未变的报价和数组保留引用；排名缓存只在报价、筛选、平台可用性或过期边界改变时失效。列表每页最多 30 条、报价详情按需展开。切换市场或隐藏页面关闭 SSE 和请求，后台继续采集；实际浏览器验证切换到原油后，合约 SSE 客户端数量从 1 降为 0。

可复现检查：

```powershell
node --experimental-strip-types tests/perpetual-performance.mjs
```

环境为 Windows 原生 Node.js 24.15.0、Intel i5-14600KF，未使用 WSL。下面是一次受控测试：5,000 条报价、1,000 标的、5 平台、100 帧，每 10 帧改变 1% 报价；各行计量范围不同，不代表公网端到端延迟，也不代表高波动行情固定节省同一比例。

| 测量 | 结果 |
| --- | --- |
| 排名全表计算次数 | 200 → 10 |
| 对应累计排名计算时间 | 215.51 → 14.33 ms |
| 完整 JSON / 50 条更新增量 JSON | 1,776,143 / 19,842 字节 |
| 该受控增量帧 gzip 后 | 915 字节；测试数据重复度较高 |
| 后台 5,000 报价快照统计 | 平均 0.21 ms |
| 后台增量检测 | 平均 2.83 ms |
| SQLite 首次 5,000 条写入 | 48.38 ms |
| SQLite 50 条增量批次写入 | 平均 6.37 ms |

另用真实公开 WS 同时连接全部 10 平台，收到约 4,300 条合约报价、50 条分片连接；当时一个活跃页面的单帧处理采样约 12–14 ms，写入批次采样约 38–80 ms。该次真实帧变化约 1,200–2,000 条，未压缩增量约 0.64–1.02 MB，不能用上述 1% 受控场景的 98.9% 缩减率替代实际行情表现。

运行时预留只读诊断 `/api/monitors/perpetual/diagnostics`，沿用登录保护，显示 `quotes`、`connections`、`clients`、`pendingWrites`、`lastWriteMs`、`lastPublishMs`、`frameBytes`、`lastFrameUpdates`。`frameBytes` 是压缩前大小；`lastPublishMs` 包括汇总、序列化和写入发送缓冲，不包含异步压缩及公网传输耗时。通过这些字段判断行情覆盖增加、连接重试或慢客户端对资源的影响，无需开启逐条行情日志。

回归测试覆盖增量删除/完整校准、无基线恢复、断流过期、慢客户端跳帧重建、身份变化清空旧价、存储失败重试，以及保持 SSE 打开的服务优雅退出。桌面及 390px 手机页面验证搜索、全部报价、平台明细和市场切换，无页面横向溢出。

## 2 核 / 2 GB 反馈后的修复

首版真实接入每秒约 20,031 条 WS 消息、5.44 MiB 数据，单页面解压后约 819 KiB/s；仅测试 1% 报价变化不足以反映这种持续负载。另外发现两类恢复缺陷：只有心跳没有行情时看门狗不重连；原生 WebSocket 对不响应 Close 的服务端长期停在 CLOSING，重连后旧 TCP 仍保留。页面还把缺少盘口字段算成“过期”，并且隐藏的原油、海力士和设置模块仍有轮询。

本轮先减少需要处理的数据，再减少重复工作：

- Binance 使用全市场 5 秒 BBO，Lighter / RH-Lighter 用单条汇总流和真实重新订阅快照。Bybit 去掉重复 10ms Level 1，补充批量 BBO；Aster 改 WS mark/funding 加 5 秒批量 BBO；Bitget 仅主币 WS，全部合约每 5 秒批量 ticker。Hyperliquid / Entropy 保留实时 BBO，每 20 秒检查是否存在超过 15 秒或缺失的盘口，仅对这些合约补查；两者按同一主机共享 60 次/分钟预算并平滑为每秒最多一次。429 或其他辅助快照错误仅暂停补查 60–300 秒，不拆除正常行情订阅。REST 失败不会将旧值重新标记为有效；所有渠道仍保留原始价格时间。
- SSE 首次建立完整基线，随后每秒只传变化字段；没有变化的价格最多每 5 秒确认一次源时间，取消每 30 秒全量重发。`streamId`、`sequence` 和 `baseSequence` 检查连续性，缺帧立即重建，慢客户端也必须重新接收完整基线。正常流中估计时钟不随积压旧帧倒退，积压超过 12 秒会重新同步。30 秒过期、两腿 5 秒对齐的规则保持不变。
- 连接无有效行情 45 秒后进入重连检测；故障及停机调用 `terminate()`，避免等待无期限的 Close 握手。WS 关闭压缩协商，减少每连接压缩上下文；浏览器 SSE 仍使用 gzip。公共报价缓存每 15 秒批量写入 SQLite，WAL NORMAL 和 100ms 锁等待避免长时间阻塞行情处理。
- 前端只在币种目录变化时重排字母索引，价格更新复用目录；全部报价模式不计算隐藏排名。价格格式器复用，导航摘要每 5 秒采样。切换或隐藏页面时，旧监控面板、外部平台对比及设置的定时读取也暂停，恢复立即补读；组件和草稿保留，服务器采集与告警继续运行。
- “过期”与“暂无有效盘口”分别计数，并跟随币种/平台筛选；零资金费仍为有效数值，缺失数据不补零。Gate 请求小数挂单数量，避免低于一单位的真实挂单被取整为零后当成空盘口。

新增诊断包括进程 `cpuPercent`（单核为 100%，包含同进程其他模块）、`rssMb`、WS `messagesPerSecond`、事件循环 `eventLoopP99Ms` / `eventLoopMaxMs`，以及各平台的新鲜/过期/缺少盘口数量、源时钟差、未来时间拒绝计数、最近公共协议错误。CPU 和事件循环每 10 秒采样，不开启逐行情日志。

存储只覆盖最新记录，不随 tick 数增长。回归连续写入同一批 1,000 合约 60 轮，确认行数保持 1,000、主库空间复用；下线清理后只剩应保留合约。WAL 每 1,000 页自动归并，归并后按 4 MiB 限制保留空间，单次事务期间可能临时超过，无需定时删“过期行情”。配置与告警存储未改成这种缓存策略。

前端高变化基准可用 `node --experimental-strip-types tests/perpetual-client-performance.mjs` 复现：50 帧、每帧 5,000 报价均更新时间。一次本机运行中，全市场字母排序从 50 次降为 0 次（稳定目录），90 个可见价格/帧的累计格式化时间由 103.59ms 降至 1.82ms；时间字段更新帧由 1,759,099 降为 389,666 字节（未压缩）。这些是固定输入的局部计算，不代表公网延迟。

新一轮收到 4,320 条报价，20 秒起至结束 10 平台均有新鲜数据，89 帧 patch 连续且无基线错误，运行期间无主行情断线。两次真实辅助快照 429 只触发补查退避，主行情继续工作；不宣称外部接口不会限流。低流动性、没有真实双边盘口或源时间确已过期的合约仍被排除，没有借优化将其改成有效数据。

该轮 RSS 峰值 268 MiB，不能声称比旧版更低；解决的是旧连接残留和有界缓存。10 秒窗口的事件循环 P99 最大 31.47ms；一次同步 SQLite 写入约 196ms，仍会造成短暂事件循环停顿，因此也不宣称零卡顿。重写为独立存储线程属于后续可测的优化空间，不作为已交付能力。

中间一轮曾遇到所有平台同时断流及 ECONNRESET；该时段不计入上述性能对比。重连、心跳但无价格、辅助 429、序号缺口及网络恢复分别用行为测试覆盖，避免把断网时的低 CPU 当优化结果。

生产构建的浏览器验收确认：断网超过 30 秒后退出有效排行，恢复网络无需刷新；切换到原油时合约 SSE 客户端从 1 降为 0，切回恢复且保留币种搜索；合约页停留期间隐藏模块不再发出定时请求。390px 页面没有横向溢出。过期连接快照的数量明确标成“上次状态”，避免误读为当前在线平台数。

## 合约机会工作台增量优化（2026-09-21）

组合排名按发生变化或到达有效期边界的币种重算，再与已有有序结果合并；平台可用性、筛选和费用口径改变时仍完整重算。报价、资金费、手续费与现货汇率各自保留失效边界。后台 SSE 增量检查使用变化合约集合，保留删除、首帧及慢客户端完整基线；有效率统计仍每秒扫描一次。诊断新增 `lastPatchVisitedQuotes`，便于核对实际扫描量。

在 Windows 原生 Node.js 24.15.0 的受控输入中，5,000 条报价、500 个币种、10 平台产生 22,500 个正向组合。全量排名耗时中位数 6.81ms、P95 14.86ms；单币种价格更新的增量排名中位数 2.07ms、P95 4.43ms；不改变报价的元数据更新中位数 0.027ms。这是局部计算基准，不是用户 Linux 2 核 / 2 GB 机器的资源实测，也不包含公网、解压与绘制耗时。

新增功能的资源边界：

- 健康面板、提醒区域仅打开且可见时每 5 秒读取；隐藏页面或切换市场停止读取。详情组件按需加载，手机减少重复摘要，直接进入合约页不再预加载原油样式及页面。
- 历史走势复用既有分钟记录，只返回当前展开组合的最多 60 个点，保持缺口，不增加写盘频率或历史保留时间。
- 盘口只在用户手动检查时请求，共享 2 个并发、每分钟 60 次预算、12 个排队上限；缓存及订阅租期有界。现货汇率按需每分钟读取并共享缓存。盘口与汇率不写磁盘。
- 最多 20 条持续提醒规则，最长 1 小时观察窗口只存内存；配置及最近 24 小时最多 100 条通知事件持久化，不保存逐秒报价。网络发送与观察、配置保存分开，慢通知不会暂停其他规则采样。
- CPU 超过 160%（单核为 100%）或事件循环 P99 超过 80ms 时，暂缓基本面和多空比的新请求，恢复后继续；不延长报价有效期。

行为验证覆盖净价差排序、增量排名与到期、历史身份和缺口、等数量双腿成交及深度不足、结算时点计数、告警持续时长/窗口覆盖/冷却/重启去重和慢发送。生产构建浏览器验收使用受控数据，覆盖组合收藏及屏蔽、展开冻结、折叠恢复、按金额检查、提醒草稿和保存、诊断停止轮询、分页、市场切换与移动端无页面横向溢出。页面中的受控 CPU、深度及价差数字不作为真实性能或行情证据。
