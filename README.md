# Market Monitor · 市场价差监控

合并原油与海力士监控面板，保留完整图表、计算口径和后台告警。通过模块注册表、数据适配器和后台服务接口扩展新市场。

| 模块 | 保留能力 |
| --- | --- |
| 原油 | 布伦特 / WTI 标记价与价差、已收盘 15 分钟 K 线、时间筛选、月均值、历史多空资金费、等桶数 / 等名义资金费预估、价格与价差多档告警 |
| 海力士 | 正股 / ADR 同口径美元价格、实时溢价、小时历史、SMA / 布林带 / Z-score、双向多档告警 |
| 合约价差 | Binance / Bybit / OKX / Bitget / Gate 与 Lighter / RH-Lighter / Hyperliquid / Aster / Entropy 的公开永续行情、组合毛 / 净价差排名、持续性与报价收窄证据、开平仓盘口测算、模拟及手工持仓跟踪、组合自选、持续条件提醒与报价健康 |
| 公共功能 | 单一登录和导航、手机布局、切换保留图表及规则草稿、独立配置与数据、接口版本、后台状态检查 |

## Linux 一键部署和升级

Ubuntu 22.04 / 24.04、Debian 12 / 13，支持 x86_64 和 ARM64：

```bash
curl -fsSL https://raw.githubusercontent.com/hxx344/market-spread-monitor/main/deploy/install.sh | bash
```

首次自动安装依赖与专用 Node.js、构建、生成登录密码、创建 SQLite 行情库、导入已有历史、注册 systemd 并启动采集。完成后访问 `http://服务器IP:3000`，使用终端显示的账号密码登录。再次执行同一命令即可升级，保留配置与数据库；新版启动失败时自动恢复原服务。

首页由服务器直接读取数据库并渲染已有报价与走势，首次打开即可看到已保存的数据，无需等浏览器启动后再取数。页面启动后继续刷新；旧数据保留原始采集时间，尚未采集到的报价显示为空。

首屏已有的历史不立即重复下载，报价照常刷新，历史从下一轮定时检查接续；没有首屏历史时立即取数。原油页面每 60 秒检查报价和 K 线、每 5 分钟检查历史资金费；调度不依赖服务器与浏览器的时钟是否一致。页面隐藏时暂停请求，切回页面、网络恢复或从浏览器历史返回时立即补刷。K 线只在每 15 分钟收盘后追加。原油明细每页 200 条，可翻页访问全部记录；曲线和统计仍使用完整历史。相同数据复用图表，鼠标移动按绘制帧处理。测试条件与结果见 [前端性能验证](docs/PERFORMANCE.md)。

升级会按变化执行：版本与配置未变、服务健康时直接结束；仅配置变化或服务停止时只恢复服务；普通代码更新会复用未变的依赖，空间允许时复用 Next.js 编译缓存，再构建新代码。依赖清单、npm 配置或运行环境变化时才重新安装依赖。从旧安装器升级后，首次成功部署会建立这些复用记录。

每次执行都会先清理安装器管理的过期版本，默认保留当前版本和一份成功回退版本；实际运行目录、源码及数据所在目录额外保留。下载、复制依赖和构建前检查磁盘容量与 inode，空间不足时回收本项目的 npm 下载缓存和 Webpack 编译缓存，仍不足则在切换服务前停止并显示所需空间。旧安装器保留的多份依赖与构建产物也会自动回收，避免每次升级持续累积。数据库的容量说明不包含这些部署文件。

只清理旧版和可重建缓存，不升级、不重启服务：

```bash
curl -fsSL https://raw.githubusercontent.com/hxx344/market-spread-monitor/main/deploy/install.sh | bash -s -- --cleanup
```

清理保留配置、数据库、运行所需文件和一份回退版本；不处理其他应用的数据或系统日志。需要同时升级时直接执行上方原安装命令即可。

新服务使用独立目录。如果同机已有原来的面板，指定空闲端口：

```bash
curl -fsSL https://raw.githubusercontent.com/hxx344/market-spread-monitor/main/deploy/install.sh | bash -s -- --port 3001
```

在面板顶部的“统一飞书告警”中保存一次 Webhook 和可选签名密钥，原油、海力士及后续模块共用，立即生效，无需重启。各模块的阈值、开关、冷却和发送记录仍独立，默认关闭消息发送。连接测试也集中在统一设置中。

升级时自动迁移原海力士配置及 `OIL_FEISHU_WEBHOOK_URL` / `OIL_FEISHU_WEBHOOK_SECRET`。只有一个机器人或两处配置相同时直接沿用；不同则在统一设置中选择已有机器人或填写新机器人，保存前暂停发送。统一配置保存于数据目录的 `notifications.json`，不会向浏览器回传完整 Webhook 或密钥；清除后重启也不会重新导入旧配置。如机器人开启关键词校验，请添加“告警”，让两个模块的消息都能通过。

后台独立于浏览器运行：海力士每 10 秒检查，原油默认每 30 秒检查。各模块独立保存规则、修订号、回差、冷却、触发状态和发送记录。运行、HTTPS 与已有配置迁移见 [部署说明](deploy/README.md)。

Linux 服务持续采集并写入 `ALERT_DATA_DIR/market.sqlite`：海力士报价每 10 秒、原油报价默认每 30 秒、海力士小时历史与原油 15 分钟历史每 60 秒、原油日线与两类已结算资金费每 5 分钟。首次导入仓库中的真实历史，之后从数据库接续增量更新并回补缺口；行情快照和逐条观测在同一事务内保存。原油与海力士页面只读取已保存的数据，打开、刷新和切换页面都不会调用交易所。合约日常行情共享后台缓存；用户主动检查盘口或开启跨计价币时，可触发有界的公开深度 / 汇率查询。没有任何页面打开时也会继续采集，进程重启后立即可读上次记录。

采集失败保留数据及原采集时间，并标记过期；告警只使用成功落盘且未过期的报价。数据库存储失败会使健康检查降级并暂停告警。数据库位于版本目录之外，升级和回滚不会重建已有数据，不需要安装独立数据库服务。

## 本地运行

### 合约价差监控

“合约价差”模块在常驻 Node 后台自动发现各平台正在交易的线性永续合约，优先使用 WebSocket 汇总行情。Binance 使用 5 秒全市场盘口流；Kraken 使用公开 Futures ticker 流，接入 flexible linear USD 永续，保留完整买卖价与源时间，不把未确认的资金费金额当作费率；Lighter / RH-Lighter 使用汇总流并定期重取真实快照；Hyperliquid / Entropy 保留盘口推送并用 WS 请求补充确认。Bybit / Aster 使用 WS 加每 5 秒一次批量 REST 盘口快照；Bitget 的 BTC / ETH / SOL 使用 WS，全部合约每 5 秒读取一次批量 ticker 快照，避免高频全市场消息挤占小服务器资源。实际更新周期另含接口响应时间。REST 同时用于合约目录、计价单位与资金费周期。市场目录每 5 分钟刷新，连接失败或只有心跳而无有效行情时自动重连。仅接入公共行情，无需交易账户或钱包。

浏览器通过同源、已有登录保护的 SSE 每秒接收变化字段，首次连接同时读取后台快照，避免代理缓冲推送时一直空白；推送和完整快照均支持 gzip。帧序号检测遗漏后立即重建数据基线，不再定时重传全市场；代理不支持 SSE 时降级为每 5 秒读取后台快照，不重复访问交易所。快照请求超过 12 秒会显示超时并释放请求，5 秒后自动重试；手动刷新也可重试，迟到响应不会覆盖恢复后的行情。登录失效、HTTP 错误或无效数据会显示具体原因。切换面板或隐藏页面暂停浏览器更新，后台采集继续运行。开发网页预览无常驻采集时明确显示未连接，请使用下方 Windows 完整后台命令，或 Linux 一键部署命令启动。

盘口毛价差为 `(卖出平台买一价 / 买入平台卖一价 − 1) × 100%`；标记价模式只反映估值差。报价按每一单位基础资产归一，明确支持的 `1000` 等倍数合约会换算。按官方元数据隔离同简称的股票、商品、Pre-IPO 和不同代币；已核实的 Bybit / Entropy 四只每股合约仍可配对，具体规则见 [标的身份说明](modules/perpetual/IDENTITY_RULES.md)。默认只比较相同计价币。开启跨计价币后，按现货买卖汇率将两腿换算至 USDT；USDC / USD1 / USDG 使用 Gate 现货盘口，USD 使用 Kraken USDT/USD 买卖价反向换算；缺失或超过 3 分钟的组合不参与排名，不假定任何外币兑价为 1。汇率在后台每分钟有界刷新并保留源时间。价格与资金费各自保留更新时间，资金费更新不会刷新旧盘口；超过 30 秒的价格、两腿时间差超过 5 秒的组合不参与有效排行，缺失字段显示 `—`。资金费差按每腿实际周期折算为 8 小时值，保留零费率，缺少周期时不估算。Bybit 的 WS 只推送变化字段；现有每 5 秒批量 ticker 请求同时确认资金费率、周期和下次结算时间，避免未变化的费率被误判过期，不增加请求。资金费率超过 5 分钟没有有效确认时仍显示 `—`。

价差是盘口顶层的毛价差，不包含手续费、滑点、市场深度及资金费变化。同一币种的不同做多/做空平台与合约组合各占一行，可按毛价差或扣除 taker 往返费及滑点预算后的净价差排序，最低阈值跟随所选口径；缺失手续费不参加净排序。每页 30 个组合，组合可独立收藏或屏蔽，旧币种自选保留。展开后用“成交与持有 / 质量依据 / 平仓与跟踪 / 各平台报价”切换详情；工作区可切换“发现机会 / 持仓跟踪”，不执行交易。原油、海力士原有图表与飞书规则照常保留。

交易所目录明确公布下架计划时，在排名的平台腿、展开明细及全部报价中标记“即将下架”，并显示北京时间；只有退市标志、没有具体时间时显示“下架时间待公布”。每 5 分钟复用批量目录核对，不逐币抓取公告，不增加行情轮询；仅标记变化不重连 WS，也不刷新价格时间。到达已知下架时间后显示“已到下架时间”，下次成功目录刷新移除该合约。**未标记不代表平台没有公告**：各平台公开字段覆盖不同，支持范围与来源见[下架标记说明](docs/PERPETUAL_DELISTING.md)。

最新合约快照每 15 秒批量保存于 `ALERT_DATA_DIR/perpetual/market.sqlite`，每个合约只保留一条、覆盖更新，不保存逐笔或历史快照，体积随合约数量变化而不是随运行天数累积。重启可显示原时间的旧报价，连接恢复后更新；正常退出会保存最后一批。这个可重建的行情缓存使用 WAL NORMAL，异常断电可能丢失最近缓存批次，配置、告警和其他模块的存储策略不变。

“聚合质量”分开显示价差持续性、报价收窄证据及资金费收入方向，市值、FDV、官方账户多空比作为辅助。稳定正价差本身不能获得高等级，稳定净支出也不会得到资金费收入分。收窄研究复用近 24 小时真实数据，每 5 分钟一个点，分别统计 1 / 4 / 8 小时不重叠完整窗口内入场报价价差是否减半；缺口与未结束窗口不计成功或失败，结果不是平仓收益或盈利概率。评分要求至少 145 点（跨度至少 12 小时）及 6 个完整 1 小时窗口，冷启动显示资料不足；缺失项不补零。现有质量历史仍最多保存 24 小时 / 1440 个压缩分钟桶，没有新增磁盘字段或写入频率。手续费按两腿合约公开普通账户 taker 费率计算，VIP 可逐平台覆盖，未知不按零；滑点默认 0.10% 可修改。权重、来源与资源边界见 [聚合质量说明](docs/PERPETUAL_QUALITY.md)。

展开质量依据还可查看“跨所多空概览”：按当前币种的五家 CEX 官方 USDT 合约账户比例等权汇总，显示参与家数、来源时间和每家缺失原因。至少两家新鲜且统计时点接近的数据才出值；这不是全网真实账户人数加总，不替代两腿拥挤度评分。后台按需共用限速和最多500条缓存，仅保留内存最新值，不新增多空历史存储。

展开某个价差详情时，本页暂停行情刷新，固定展开时的排名、页码、平台组合与报价，避免阅读时位置跳动。收起、翻页、修改筛选或切换监控后恢复。报价仍按来源时间显示过期，超过5分钟的资金费差显示「—」；后台行情采集与低频质量资料查询继续运行。暂停快照只保存在当前页面内存，不写入磁盘。

成功刷新目录会自动删除已下线合约，SQLite 复用删除后的空间。写入日志每 1,000 页自动归并，归并后按 4 MiB 上限保留日志空间（归并前单次批量写入可能临时超过），关闭数据库也会回收日志。**无需另设定时清理过期报价任务**；报价超过 30 秒只代表不能参加实时排行，不会生成额外历史记录。数据库与配置位于版本目录之外，现有一键升级流程保留它们并安装新增依赖，无需手动迁移。

- `GET /api/monitors/perpetual/quote`：平台连接状态及全部最新报价。
- `GET /api/monitors/perpetual/opportunities-v2`：七所 CrossEx 模拟接口（Binance / Bybit / OKX / Gate / Kraken / Hyperliquid / Lighter，排除 Deribit），保留原始报价、结算币与合约身份，附 USDC / USD 买卖汇率。页面“CrossEx 七所”可一键选择相关平台并开启跨币比较；最终模拟资格由 CrossEx 目录再次核对。
- `GET /api/monitors/perpetual/opportunities`：CrossEx 只读模拟联动，返回最多 200 条 Binance / Bybit 同币种 USDT 永续正毛价差信号，以及独立保留的支持市场原始报价；盘口有效期 10 秒。沿用已有登录和后台行情，不发单、不新增轮询。身份范围、估值时效与完整契约见 [CrossEx 模拟接口](docs/CROSSEX_SIGNALS.md)。
- `GET /api/monitors/perpetual/stream`：相同数据的 SSE 推送，仅常驻服务支持。
- `GET /api/monitors/perpetual/diagnostics`：已登录用户可查看当前连接、客户端、待写报价数及最近一帧处理/写库耗时，详见 [性能说明](docs/PERFORMANCE.md)。
- `POST /api/monitors/perpetual/depth`：手动按目标金额检查两腿盘口。
- `POST /api/monitors/perpetual/exit`：按相同标的数量卖出多腿、买回空腿，估算当前盘口平仓收益。
- `GET / POST /api/monitors/perpetual/paper`：模拟 / 手工持仓登记、资金费确认、结束及有界复盘记录。
- `GET /api/monitors/perpetual/fx`：有界缓存的现货换汇买卖价。
- `GET / PUT /api/monitors/perpetual/alerts`：组合观察、持续条件和飞书提醒配置，默认关闭。
- 参考交互：[Panda 价差监控](https://pandazhai.com/monitor/)。行情直接来自各平台公开接口。

合约新增功能与资源约定见 [机会工作台](docs/PERPETUAL_WORKSPACE.md)：顶部显示当前筛选的组合数、正净价差数量和报价有效率，健康面板按需每 5 秒读取诊断。详情展示该组合最多 60 个真实分钟采样，缺口断线，不扩展历史保留期。

[按金额检查盘口](docs/perpetual-execution.md) 只在点击时执行，Lighter 两站取单次 WS 快照，其余平台按需 REST；最多 10 个合约、2 个并发、每分钟 60 次上游请求。两腿匹配相同标的数量，盘口不足不当作完整成交。持有期情景按真实下次结算时点与周期估算，假设未来费率不变，退出残余价差可调整。

平仓测算支持手填开仓均价、相同标的数量、已付开仓费用、累计已结算资金费及两账户投入本金；按退出方向逐档匹配盘口和当次成交金额计算 taker 费用，区分 USDT 净额、单腿名义收益率与投入本金收益率。当前仅支持两腿均为 USDT 计价及结算的线性合约，深度不足、过期或费用未知不输出完整净收益。它是估算，不会发出订单。

模拟 / 手工持仓跟踪复用后台报价，每分钟观察一次并有界落盘；页面关闭也继续运行，不新增交易所轮询。最多 20 个活动记录、100 个已结束记录，后者保留 30 天；活动曲线最多 288 个 5 分钟点，已结束仅保留 12 个概览点。新增JSON文件最多 1,000,000 字节，原子替换时临时峰值约2 MB，这不是整个项目的磁盘上限。资金费只使用用户登记的累计净额，跨结算时点提示再次确认，不根据预估费率伪造到账。目标触达和超时只更新站内观察状态，没有自动交易或自动平仓。详情见 [机会工作台](docs/PERPETUAL_WORKSPACE.md)。

合约机会提醒默认关闭，支持最多 20 个独立方向规则。连续达标与窗口占比同时满足后使用统一飞书发送；缺失、过期或停机间隔中断计时，持续同一机会不会重复提醒。规则与最近 24 小时最多 100 条发送记录保存于合约目录，关闭网页后已保存的观察规则继续运行。

## 扩展接口

- `GET /api/monitors`：`schemaVersion: 1` 和模块清单。
- `GET /api/monitors/{id}/quote`：Linux 返回数据库最新报价及 `collection` 采集状态，过期数据标记 `status: "snapshot"`，从未收到数据时返回 503；原油网页预览获取失败时保留 Binance 最近成功报价或真实备用快照并标明状态。
- `GET /api/monitors/{id}/history`：历史与采集时间，失败保留真实快照并标明状态。
- `GET /api/monitors/oil/candles/15m`：原油同一 UTC 时段已收盘的 15 分钟 K 线。Linux 只读 Binance 独立数据集 `oil/binance/candles/15m`；原 Hyperliquid 库记录保留，不混入新曲线。
- `GET /api/monitors/{id}/exchanges/{exchange}/quote`：Bybit / Binance 实时报价及每腿资金费率、结算周期和下次结算时间；`exchange` 为 `bybit` 或 `binance`，原油还支持 `hyperliquid`。Linux 只读数据库，首次无数据返回 503，更新失败保留上次报价并标明过期。
- `GET /api/monitors/oil/funding`：原油已结算资金费历史。
- Linux 专用告警接口按模块 ID 隔离。

主要接入点：`lib/monitors.ts`（描述）、`lib/monitor-service.ts`（数据）、`app/monitor-hub.tsx`（面板）、`server/monitor-services.mjs`（可选后台）。新增市场可以复用公共 HTTP 层，详见 [扩展指南](docs/EXTENDING.md)。

## 数据与历史更新

使用 Hyperliquid / XYZ、Bybit、Binance 公共行情，不需要钱包或交易 API 密钥。

- 交易所实时对比区显示原油百分比价差、海力士绝对价差与溢价率，以及做空和做多价差的当前预估年化资金费。Bybit / Binance 每 15 秒更新；原油两腿为 `BZUSDT / CLUSDT`，海力士为 `SKHYUSDT / SKHYNIXUSDT`。后两家的合约报价均为 USDT 标记价，正股接口已完成换汇；Hyperliquid 单独标注 USD，海力士沿用中间价。只比较各交易所内部两腿，不把 USD 和 USDT 假定为严格等值。
- 对比区原油使用等桶数，海力士使用 10 份 ADR 对 1 股正股。做空价差年化为 `(空腿数量 × 计费价格 × 周期费率 / 周期小时 − 多腿数量 × 计费价格 × 周期费率 / 周期小时) / 两腿总名义 × 8760`；做多为相反数。Bybit / Binance 的计费价格为标记价，Hyperliquid 为预言机价。每条腿分别读取当前结算周期，不固定为 8 小时；费率、周期或结算时间缺失时保留价格、年化显示 `—`，真实零费率显示零。当前费率可能在结算前变化。
- 原油主面板的实时价格、历史曲线、资金费和告警统一使用 Binance；海力士主面板仍使用 Hyperliquid。原油 Hyperliquid / Bybit 继续作为实时对比行，Linux 每 15 秒保存五组独立对比报价，首屏直接读库。
- 原油价差为 `(BZUSDT − CLUSDT) / CLUSDT × 100%`，以 WTI 为基准，保留正负号；两腿价格仍以 USDT/桶展示。当前行情使用标记价；主图与迷你图采用两腿同一 UTC 时段的 **15 分钟 K 线收盘百分比价差**，默认近 1 周，可选 1 天、1 周、1 月及全部历史。图表显示北京时间，未收盘 K 线排除，缺口断线；不把单腿高低价相减构造价差蜡烛。月均值取逐根百分比价差的算术平均，首尾及相邻 K 线的价差变化用“百分点”。历史继续保存两腿原始价格，展示时重算，无需迁移。新增告警默认使用百分比，回差单位为百分点；已有 `spread` 绝对价差规则及历史记录继续按金额判断和显示，新百分比指标为 `spreadPercent`。
- Binance 两合约于 2026-04-01 上线，15 分钟公共历史可分页回溯，真实归档从 `2026-04-01 09:00 UTC`（北京时间 17:00，首根为上市时段的部分 K 线）开始，超过 16,000 根。`public/oil/data/binance-15m.json` 保存初始记录；后台增量更新、重取最近 24 小时并回补历史缺口，不沿用 Hyperliquid 的 5,000 根回溯限制。
- 当前资金费按每腿实际周期折算小时率，支持等桶数和等 USDT 名义。历史采用**两腿等 USDT 名义**，每次做空净结算率为 `(r_BZ − r_CL) / 2`，做多为相反数；两合约目前每 4 小时结算。累计为所选精确时间区间内实际结算净率之和，年化＝累计净率 ÷（有效结算次数 × 4 小时）× 8,760，不复利。曲线按 UTC 日汇总；日均小时率也按实际覆盖小时计算，缺失结算不补零，明细仅在结算时点显示一次。
- 初始资金费归档 `public/oil/data/binance-funding-2026.json` 中，两合约公共接口均缺少 `2026-06-24 04:00 UTC` 的记录；页面将其计入缺失覆盖，后续采集会继续尝试回补。
- 永续合约本身没有到期日，但底层指数按 [Binance 展期规则](https://www.binance.com/en/support/faq/detail/0675298e133640f48aab7e3bb4ae1d38) 在近月、远月之间逐步调整权重。Brent 与 WTI 可能对应不同交割月，价差包含换月与期限结构影响；资金费年化仅计算资金费，不包含展期等因素带来的价格盈亏。程序只监控，不执行换月交易，也未单独分解展期贡献。
- 升级后新原油数据存入 `oil/binance/*`，已有 Hyperliquid 快照和逐条历史原样保留，以便回滚。告警阈值、开关和历史发送记录保留，旧记录标明 Hyperliquid；换源时重置触发状态并增加配置修订号，之后按 Binance 报价重新判断，新告警明确标记来源。
- 海力士价差为 `xyz:SKHY − xyz:SKHX / 10`，溢价率为 `(SKHY / (SKHX / 10) − 1) × 100%`。实时使用一次 `allMids` 返回的两侧报价，历史使用已完成共同小时。SKHX 已是美元价格，不二次换汇。
- 海力士卡片净资金费按空 10 份 ADR、多 1 股正股计算。设两腿预言机价格为 `P_ADR`、`P_正股`，小时资金费率为 `r_ADR`、`r_正股`，年化率为 `(10 × P_ADR × r_ADR − P_正股 × r_正股) / (10 × P_ADR + P_正股) × 24 × 365`，界面显示百分比，正值表示净收取。数据来自 `metaAndAssetCtxs`，不含杠杆、手续费或价差变化；资金费获取失败显示 `—`，正常报价和溢价告警继续工作。
- 海力士历史资金费采用与原油历史图一致的**两腿等名义金额**口径：做空价差为空 ADR、多正股，每个已结算小时净率为 `(r_ADR − r_正股) / 2`，做多为相反数。历史接口没有结算时的预言机价格，因此这与顶部固定 10:1 配仓的当前预估年化口径不同。历史面板提供小时费率、累计资金费和累计年化三种曲线；累计为所选区间有效小时之和，年化为该和除以有效小时数再乘 `8760`，不复利。缺口断线、不补零，同时显示覆盖小时数；累计值仅包含已覆盖部分。
- 历史资金费通过 `/api/monitors/hynix/funding` 获取，每 5 分钟检查并增量回补缺口。`data/hynix-funding.json` 保存真实备用记录，更新失败保留最近成功数据及原获取时间；初始范围从 2026-07-10 15:00 UTC 结算开始，对应现有价差图首个完整价格小时结束。维护归档可运行 `node --experimental-strip-types scripts/archive-hynix-funding.mjs`。
- 保留原仓库的真实快照和边界：原油 Binance 历史自 2026 年 4 月上市后持续积累，旧 Hyperliquid 归档独立保留；海力士自上市后的首个完整小时开始。缺失数据保留断点。

## 工作台摘要与 CrossEx 联动

工作台使用 `GET /api/hub/summary?schemaVersion=2` 读取所选模块的采集缓存，返回源时间、`health.state/message/staleAfterSeconds` 和紧凑指标；使用 `monitor=oil|hynix|perpetual` 选择模块，默认原油，保留原工作台指标 key、单位和时间口径，各模块故障独立显示。读取摘要不触发公网行情请求、不读取完整历史。无参数仍返回 v1；无常驻采集器的网页预览明确返回 offline。

合约价差的“CrossEx 推送筛选”可选择只推送双方都有可交易现货、且至少一条共同网络双向充提正常的机会。默认关闭，保存到服务器后页面关闭仍生效；代币地址须匹配，未知或过期资料不推送。当前已接入 Binance、Gate 的公开数据，其他平台暂时无法核验，开启后排除。规则只过滤新机会，保留持仓报价。[数据覆盖与筛选口径](docs/CROSSEX_SIGNALS.md#可选的双边现货与充提筛选)。

合约价差列表的币种旁可直接点击“屏蔽并隐藏”，保存后该币种从“价差排名”“全部报价”和展开报价中隐藏，同时停止向 CrossEx 提供所有交易所及方向的新机会。上方“CrossEx 推送筛选”的屏蔽名单可手动添加或解除，解除后按当前筛选重新显示。统计和分页排除已屏蔽币种，搜索、自选和重置本地筛选不会绕过屏蔽；名单变化时关闭暂停详情并恢复行情。名单保存在服务器，刷新或重启后保留，最多 200 个；独立于充提开关生效。隐藏仅作用于机会列表，后台原始报价继续用于已有持仓及独立手动配对。

CrossEx 的 `opportunities-v2` 继续返回兼容的完整 JSON，支持标准 HTTP gzip。报价、目录、汇率、推送设置或充提资料版本变化时重新计算；源版本相同的投影最多复用 10 秒，充提资料过期立即使缓存失效。信号的 `observedAt/expiresAt` 受原报价、汇率及启用后的充提证据时效限制，响应时间不会延长可用期限；重启会丢弃投影缓存并重新生成完整结果。解压后的响应大小仍由 CrossEx 限制。

嵌入工作台时，模块只接受独立代理来源对应的 `hub.localhost` 父页面消息；握手前暂停前端读数，模块隐藏后停止轮询与推送，后台采集和告警继续运行。恢复时立即读取最新数据。永续组合详情中的“在 CrossEx 查看”只定位币种和多空方向，不执行模拟；未连接工作台时不显示跨模块入口。保存配置或模拟记录后通知工作台更新摘要。

可在 Windows 原生 Node 下运行 `node --experimental-strip-types scripts/benchmark-crossex.mjs` 复现合成基准。2026-09-22，4,900 条合成报价、200 个候选：完整投影平均 67.256 ms，同源版本复用 0.019 ms；3,783,790 字节 JSON 经 gzip 后为 98,843 字节（减少 97.39%，压缩平均 7.196 ms）。此处是确定性合成数据，非线上吞吐承诺；连续更新的版本仍需完整重算。

升级沿用上方一键部署命令；本次没有新增依赖、环境变量或数据迁移。已有安装输入摘要覆盖新增源码与测试，配置和数据保留。
